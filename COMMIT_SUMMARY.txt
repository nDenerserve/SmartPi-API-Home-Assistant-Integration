feat: initial release of SmartPi HA integration (v1.0.0)


SCOPE OF CHANGES
----------------
This commit represents the first complete, production-ready release of the
SmartPi custom integration for Home Assistant. It covers all source files,
branding assets, documentation, and configuration.


CHANGED FILES
-------------

custom_components/smartpi/__init__.py
  - Entry setup and teardown logic
  - Platform forwarding for sensor, number, switch, select
  - Options-change listener that triggers integration reload

custom_components/smartpi/coordinator.py
  - DataUpdateCoordinator polling /livedata every 30 s
  - JWT authentication with automatic token refresh on 401
  - Unified data dict keyed by (phase, measurement_type)
  - Read/write access to SmartPi AC config and main config
  - English docstrings added to all methods

custom_components/smartpi/config_flow.py
  - Config flow: host, port, optional credentials, duplicate detection
  - Re-authentication flow for credential updates
  - Options flow with three sections:
      - Sensor selection (stored in HA options, triggers reload)
      - Device settings: name, GPS, log level (written to device)
      - AC settings: power frequency, sample rate, integrator
  - Measurement labels translated to English
  - English docstrings added throughout

custom_components/smartpi/sensor.py
  - Read-only sensor entities for 8 per-phase measurement types
  - Total power sensor from the separate /livepower endpoint
  - Sensor descriptions updated with English value_label strings
  - English docstrings added

custom_components/smartpi/number.py
  - Per-phase number entities for calibration and hardware parameters
  - Entities for phases 1–4: current calibration, CT primary current,
    GUI max current
  - Entities for phases 1–3 only: reference voltage, voltage calibration
  - Entity names translated to English
  - English docstrings added

custom_components/smartpi/switch.py
  - Per-phase switch entities to enable/disable measurement channels

custom_components/smartpi/select.py

NOTABLE DECISIONS
-----------------
1. Credentials are optional. The integration works in read-only mode (sensor
   data only) without a username or password. Configuration entities require
   credentials and are skipped at setup if the AC config cannot be loaded.

2. All configuration entities are disabled by default. This avoids cluttering
   the device page for users who only need sensor data.

3. Config writes use a two-step pattern: update the in-memory cache first,
   then write the entire config object back to the device. This matches the
   SmartPi API's bulk-write semantics and avoids partial updates.

4. The total-power value comes from a separate /livepower endpoint. If this
   endpoint fails (e.g. when a reverse proxy returns HTML instead of JSON),
   the error is logged at DEBUG level and the sensor simply has no value for
   that poll cycle.

5. The unique ID is the device serial number. If no serial is returned by the
   device (firmware edge case), the config entry ID is used as a fallback.
