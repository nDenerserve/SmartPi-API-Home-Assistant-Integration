OVERVIEW
---------
Implementation of a complete Home Assistant custom integration for the
SmartPi AC energy meter (enerserve GmbH). The integration communicates
exclusively via the SmartPi REST API and supports multiple devices
on the same network.

Tested against SmartPi device 10.30.0.71 (smartfarm0004,
Serial 000000004b5f379c, HA 2026.5.1).


NEW FILES
------------

custom_components/smartpi/__init__.py
  - Entry point for the integration
  - Registers the Sensor, Number, Switch and Select platforms
  - Starts the DataUpdateCoordinator and loads the SmartPi configuration
  - Triggers a reload when options are changed (sensor selection)

custom_components/smartpi/manifest.json
  - Integration metadata (Domain: smartpi, iot_class: local_polling)
  - No external Python dependencies (aiohttp is available internally in HA)

custom_components/smartpi/const.py
  - Constants: Domain, default port (80), polling interval (30 s)
  - API paths: login, livedata, livepower, read/write configuration
  - Measurement types, CT types, log levels, mains frequencies

custom_components/smartpi/coordinator.py
  - DataUpdateCoordinator (30-second polling)
  - Retrieves /api/v1/smartpiac/livedata (all phases and measured values)
  - Retrieves /api/v1/smartpiac/livepower (total power)
  - JWT authentication with automatic retry on 401
  - Methods for reading and writing the SmartPi configuration
    (Basic settings via writesmartpiconfiguration,
     Measurements via writesmartpiacconfiguration)
  - Write format: {‘type’: ‘smartpiconfig’/“smartpiacconfig”, ‘msg’: {...}}
  - Workaround: SmartPi sends Content-Type: text/plain instead of application/json
    → resp.json(content_type=None) in all places

custom_components/smartpi/config_flow.py
  - Config Flow (setup dialogue) with fields:
      Host/IP, Port (default 80), Username (optional), Password (optional)
  - Connection test against /api/v1/smartpiac/livedata during setup
  - SmartPi serial number as unique_id → prevents duplicate configuration
  - Support for multiple instances (one instance per SmartPi device)
  - Re-Auth Flow: re-enter password if it has been changed on the SmartPi
  - Options Flow (Configure button) with three menu items:
      1. Sensor selection   – which measured values should appear in HA
      2. Basic settings – Name, Latitude, Longitude, Log level
                             (writes directly to the SmartPi)
      3. Measurements (global) – mains frequency, sampling rate, integrator
                             (writes directly to the SmartPi)
  - Compatible with HA 2026.x: config_entry in OptionsFlow without __init__ setter

custom_components/smartpi/sensor.py
  - Generates sensor entities for all measured values reported by the SmartPi
  - Supported types per phase 1–3:
      Current (A), Voltage (V), Active power (W), Power factor (cos φ),
      Frequency (Hz), Energy consumed (Wh), Energy fed in (Wh),
      Net energy (Wh)
  - Phase 4 (neutral): current only
  - Additional ‘Total power’ sensor from /api/v1/smartpiac/livepower
  - Filtering via Options (sensor selection): only activated types appear
  - Correct HA device classes (CURRENT, VOLTAGE, POWER, POWER_FACTOR,
    FREQUENCY, ENERGY) and STATE_CLASS_MEASUREMENT
  - All sensors of an instance are grouped as a single HA device
    (identified by serial number)

custom_components/smartpi/number.py
  - Editable Number entities for per-phase configuration (Measurements tab)
  - Disabled by default (entity_registry_enabled_default = False)
  - Phase 1–4: Calibration factor for current, CT primary current, display maximum current
  - Phase 1–3: Reference voltage (V), voltage calibration factor
  - Writes immediately via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/switch.py
  - Writable Switch entities for per-phase configuration (Measurements tab)
  - Disabled by default
  - Phase 1–4: Measure current (MeasureCurrent), reverse current direction
               (CurrentDirection)
  - Phase 1–3: Measure voltage (MeasureVoltage)
  - Writes immediately via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/select.py
  - Editable Select entities for per-phase configuration (Measurements tab)
  - Disabled by default
  - Phases 1–4: Current transformer type (CTType)
    Options: YHDC_SCT013, YHDC_SCT006, YHDC_SCT023R, YHDC_SCT0400,
              YHDC_SCT800, Rogowski
  - Unknown values are dynamically added to the selection list
  - Writes immediately via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/strings.json
  - UI text (German) for Config Flow, Options Flow and error messages

custom_components/smartpi/translations/de.json
  - German translations (Config Flow, Options Flow)

custom_components/smartpi/translations/en.json
  - English translations (Config Flow, Options Flow)


TECHNICAL NOTES
-------------------

API specifics (SmartPi side):
  - Live endpoints do not require authentication
  - Configuration endpoints require JWT bearer tokens
  - The content type of the responses is ‘text/plain; charset=utf-8’ (not JSON)
    → aiohttp workaround: resp.json(content_type=None)
  - Write endpoints expect a wrapper object:
    {‘type’: ‘<config-type>’, ‘msg’: {<full config object>}}
  - The default port of the SmartPi web server is 1080 (direct access)
    or 80 (via reverse proxy) – Integration default: 80

Supported API endpoints:
  GET  /api/v1/smartpiac/livedata               (no auth)
  GET  /api/v1/smartpiac/livepower              (no auth)
  POST /api/v1/login                            (fetch JWT token)
  GET  /api/v1/config/readsmartpiconfiguration  (JWT)
  POST /api/v1/config/writesmartpiconfiguration (JWT)
  GET  /api/v1/config/readsmartpiacconfiguration  (JWT)
  POST /api/v1/config/writesmartpiacconfiguration (JWT)

HA version compatibility:
  - Tested with Home Assistant 2026.5.1
  - OptionsFlow without self.config_entry in __init__ (mandatory from HA 2024.x onwards)
  - Uses DataUpdateCoordinator, CoordinatorEntity, SelectSelector

  GET  /api/v1/smartpiac/livedata               (kein Auth)
  GET  /api/v1/smartpiac/livepower              (kein Auth)
  POST /api/v1/login                            (JWT-Token holen)
  GET  /api/v1/config/readsmartpiconfiguration  (JWT)
  POST /api/v1/config/writesmartpiconfiguration (JWT)
  GET  /api/v1/config/readsmartpiacconfiguration  (JWT)
  POST /api/v1/config/writesmartpiacconfiguration (JWT)

HA-Versionskompatibilität:
  - Getestet mit Home Assistant 2026.5.1
