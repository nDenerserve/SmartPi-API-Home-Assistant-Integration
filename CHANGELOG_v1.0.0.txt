ÜBERSICHT
---------
Implementierung einer vollständigen Home Assistant Custom Integration für den
SmartPi AC-Energiezähler (enerserve GmbH). Die Integration kommuniziert
ausschließlich über die REST-API des SmartPi und unterstützt mehrere Geräte
im selben Netzwerk.

Getestet gegen SmartPi-Gerät 10.30.0.71 (smartfarm0004,
Serial 000000004b5f379c, HA 2026.5.1).


NEUE DATEIEN
------------

custom_components/smartpi/__init__.py
  - Einstiegspunkt der Integration
  - Registriert die Plattformen Sensor, Number, Switch, Select
  - Startet den DataUpdateCoordinator und lädt die SmartPi-Konfiguration
  - Löst bei Änderung der Optionen (Sensor-Auswahl) einen Reload aus

custom_components/smartpi/manifest.json
  - Integrations-Metadaten (Domain: smartpi, iot_class: local_polling)
  - Keine externen Python-Abhängigkeiten (aiohttp ist HA-intern vorhanden)

custom_components/smartpi/const.py
  - Konstanten: Domain, Standard-Port (80), Poll-Intervall (30 s)
  - API-Pfade: login, livedata, livepower, Konfiguration lesen/schreiben
  - Messwert-Typen, CT-Typen, Log-Level, Netzfrequenzen

custom_components/smartpi/coordinator.py
  - DataUpdateCoordinator (30-Sekunden-Polling)
  - Ruft /api/v1/smartpiac/livedata ab (alle Phasen und Messwerte)
  - Ruft /api/v1/smartpiac/livepower ab (Gesamtleistung)
  - JWT-Authentifizierung mit automatischem Retry bei 401
  - Methoden zum Lesen und Schreiben der SmartPi-Konfiguration
    (Grundeinstellungen via writesmartpiconfiguration,
     Messungen via writesmartpiacconfiguration)
  - Write-Format: {"type": "smartpiconfig"/"smartpiacconfig", "msg": {...}}
  - Workaround: SmartPi sendet Content-Type: text/plain statt application/json
    → resp.json(content_type=None) an allen Stellen

custom_components/smartpi/config_flow.py
  - Config Flow (Setup-Dialog) mit Feldern:
      Host/IP, Port (Standard 80), Benutzername (optional), Passwort (optional)
  - Verbindungstest gegen /api/v1/smartpiac/livedata beim Setup
  - Seriennummer des SmartPi als unique_id → verhindert Doppelkonfiguration
  - Unterstützung mehrerer Instanzen (pro SmartPi-Gerät eine Instanz)
  - Re-Auth-Flow: Passwort neu eingeben wenn es auf dem SmartPi geändert wurde
  - Options Flow (Konfigurieren-Button) mit drei Menüpunkten:
      1. Sensor-Auswahl   – welche Messwerte in HA erscheinen sollen
      2. Grundeinstellungen – Name, Breitengrad, Längengrad, Log-Level
                             (schreibt direkt auf den SmartPi)
      3. Messungen (global) – Netzfrequenz, Abtastrate, Integrator
                             (schreibt direkt auf den SmartPi)
  - Kompatibel mit HA 2026.x: config_entry in OptionsFlow ohne __init__-Setter

custom_components/smartpi/sensor.py
  - Erzeugt Sensor-Entitäten für alle vom SmartPi gemeldeten Messwerte
  - Unterstützte Typen je Phase 1–3:
      Strom (A), Spannung (V), Wirkleistung (W), Leistungsfaktor (cos φ),
      Frequenz (Hz), Bezogene Energie (Wh), Eingespeiste Energie (Wh),
      Bilanzierte Energie (Wh)
  - Phase 4 (Neutral): nur Strom
  - Zusätzlicher Sensor „Gesamtleistung" aus /api/v1/smartpiac/livepower
  - Filterung über Options (Sensor-Auswahl): nur aktivierte Typen erscheinen
  - Korrekte HA-Device-Classes (CURRENT, VOLTAGE, POWER, POWER_FACTOR,
    FREQUENCY, ENERGY) und STATE_CLASS_MEASUREMENT
  - Alle Sensoren einer Instanz sind als ein HA-Gerät gruppiert
    (Identifikation über Seriennummer)

custom_components/smartpi/number.py
  - Schreibbare Number-Entitäten für per-Phase-Konfiguration (Messungen-Tab)
  - Standardmäßig deaktiviert (entity_registry_enabled_default = False)
  - Phase 1–4: Kalibrierungsfaktor Strom, CT-Primärstrom, Anzeige-Maximalstrom
  - Phase 1–3: Referenzspannung (V), Kalibrierungsfaktor Spannung
  - Schreibt sofort via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/switch.py
  - Schreibbare Switch-Entitäten für per-Phase-Konfiguration (Messungen-Tab)
  - Standardmäßig deaktiviert
  - Phase 1–4: Strom messen (MeasureCurrent), Stromrichtung umkehren
               (CurrentDirection)
  - Phase 1–3: Spannung messen (MeasureVoltage)
  - Schreibt sofort via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/select.py
  - Schreibbare Select-Entitäten für per-Phase-Konfiguration (Messungen-Tab)
  - Standardmäßig deaktiviert
  - Phase 1–4: Stromwandler-Typ (CTType)
    Optionen: YHDC_SCT013, YHDC_SCT006, YHDC_SCT023R, YHDC_SCT0400,
              YHDC_SCT800, Rogowski
  - Unbekannte Werte werden dynamisch zur Auswahlliste hinzugefügt
  - Schreibt sofort via coordinator.async_set_ac_config_phase_value()

custom_components/smartpi/strings.json
  - UI-Texte (Deutsch) für Config Flow, Options Flow und Fehlermeldugen

custom_components/smartpi/translations/de.json
  - Deutsche Übersetzungen (Config Flow, Options Flow)

custom_components/smartpi/translations/en.json
  - Englische Übersetzungen (Config Flow, Options Flow)


TECHNISCHE HINWEISE
-------------------

API-Besonderheiten (SmartPi-seitig):
  - Live-Endpunkte benötigen keine Authentifizierung
  - Konfigurations-Endpunkte benötigen JWT-Bearer-Token
  - Content-Type der Antworten ist "text/plain; charset=utf-8" (nicht JSON)
    → aiohttp-Workaround: resp.json(content_type=None)
  - Write-Endpunkte erwarten ein Wrapper-Objekt:
    {"type": "<config-type>", "msg": {<full config object>}}
  - Standard-Port des SmartPi-Webservers ist 1080 (direkter Zugriff)
    bzw. 80 (über Reverse Proxy) – Integration-Default: 80

Unterstützte API-Endpunkte:
  GET  /api/v1/smartpiac/livedata               (kein Auth)
  GET  /api/v1/smartpiac/livepower              (kein Auth)
  POST /api/v1/login                            (JWT-Token holen)
  GET  /api/v1/config/readsmartpiconfiguration  (JWT)
  POST /api/v1/config/writesmartpiconfiguration (JWT)
  GET  /api/v1/config/readsmartpiacconfiguration  (JWT)
  POST /api/v1/config/writesmartpiacconfiguration (JWT)

HA-Versionskompatibilität:
  - Getestet mit Home Assistant 2026.5.1
  - OptionsFlow ohne self.config_entry im __init__ (ab HA 2024.x Pflicht)
  - Verwendet DataUpdateCoordinator, CoordinatorEntity, SelectSelector
